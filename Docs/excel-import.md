# Excel インポート設計

## 1. 目的

営業が Excel/スプレッドシートで管理している既存データ(技術者・案件・契約)を一括登録できるようにする。
実運用への移行時に手入力を強いると採用の障壁になるため、**テンプレート出力 → 記入 → 取り込み**の流れで移行コストを最小化する。

## 2. 方式

```
[テンプレートDL] → [営業が記入] → [アップロード(プレビュー)] → [エラー修正] → [確定]
```

- フォーマットは **.xlsx**(CSV は日本語環境の文字コード問題を避けるため不採用)
- バックエンドは ClosedXML で読み書き
- プレビュー(dry-run)と確定は同じエンドポイント。確定時に同じファイルを再送する(ステートレス)
- **全件 or なし**:1行でもエラーがあれば何も取り込まない(部分取り込みによるデータ不整合を防ぐ)
- エラーは「シート名 / 行番号 / メッセージ」の単位で返す

## 3. テンプレート構成(1ブック4シート)

### 3.1 シート「技術者」

| 列 | 必須 | 形式 |
|---|---|---|
| メールアドレス | ✔ | ログインIDになる。同一判定キー |
| 氏名 | ✔ | |
| 担当営業メール | | 空欄ならインポート実行者。既存の営業ユーザーのメール |
| 自己紹介 | | 自由記述 |
| NG業務 | | 自由記述 |
| スキル | | `スキル名:年数` のカンマ区切り(例: `Java:5, AWS:2`)。スキル名は「スキルマスタ」シート参照 |

### 3.2 シート「案件」

| 列 | 必須 | 形式 |
|---|---|---|
| 案件タイトル | ✔ | 同一判定キー(削除済み案件は対象外) |
| クライアント名 | | |
| 担当営業メール | | 空欄ならインポート実行者 |
| 概要 | | 自由記述 |
| 開始日 | ✔ | 日付セル または `yyyy-MM-dd` / `yyyy/MM/dd` |
| 終了日 | ✔ | 同上。開始日以降 |
| 単価下限 | ✔ | 整数(万円)。単価上限以下 |
| 単価上限 | ✔ | 整数(万円) |
| ステータス | ✔ | ドロップダウン: `Draft` / `Open` / `Closed` / `Cancelled` |
| 必須スキル | | `スキル名:年数` のカンマ区切り |
| 歓迎スキル | | 同上 |

### 3.3 シート「契約」

1行 = 1契約。同じアサインの更新契約は行を分けて記入する。

| 列 | 必須 | 形式 |
|---|---|---|
| 技術者メール | ✔ | 「技術者」シートまたは登録済み技術者 |
| 案件タイトル | ✔ | 「案件」シートまたは登録済み案件 |
| アサイン状態 | ✔ | ドロップダウン: `Active` / `Ended` / `Cancelled` |
| アサイン開始日 | ✔ | アサインの同一判定キーの一部 |
| 契約開始日 | ✔ | 契約の同一判定キー |
| 契約終了日 | ✔ | 契約開始日以降 |
| 単価 | ✔ | 整数(万円) |
| 契約種別 | ✔ | ドロップダウン: `Initial` / `Renewal` |

### 3.4 シート「スキルマスタ」(参照用)

登録済みスキルの一覧(名前・カテゴリ)。記入はしない。
ドロップダウン(ステータス・契約種別など単一値の列)はExcelのデータ入力規則で設定する。スキル列は複数値のためドロップダウン化せず、このシートを参照して記入する。

## 4. 同一性判定と upsert

| 対象 | キー | 既存時の挙動 |
|---|---|---|
| 技術者 | メールアドレス | 氏名・担当営業・自己紹介・NG業務を更新。スキル列が空欄でなければ記載内容で全置換 |
| 案件 | 案件タイトル | 各列を更新。スキル列が空欄でなければ置換 |
| アサイン | (技術者, 案件, アサイン開始日) | 状態を更新 |
| 契約 | (アサイン, 契約開始日) | 終了日・単価・契約種別を更新 |

再取り込み(同じファイルを2回入れる)は安全(冪等)。

## 5. アカウント作成

- `Engineer.UserId` は必須のため、新規技術者の取り込みは **User(role=Engineer) の自動作成を伴う**
- 初期パスワードはサーバーが乱数生成し、**確定レスポンスでのみ一度だけ返す**(DBには ハッシュのみ保存)。営業が本人に伝達する運用
- メールアドレスが既存ユーザーと衝突し、かつそのユーザーが Engineer ロールでない場合はエラー
- 担当営業メールは既存の Sales ロールユーザーを参照。インポート実行者が Admin(Sales プロフィールなし)の場合、担当営業メール空欄はエラー

## 6. API

| Method | Path | 権限 | 説明 |
|---|---|---|---|
| GET | `/imports/template` | Sales | テンプレート xlsx をダウンロード |
| POST | `/imports/excel?dryRun=true\|false` | Sales | multipart/form-data(`file`)。dryRun=true で検証のみ |

制限: ファイル 5MB まで、各シート 1000 行まで。

レスポンス(200):

```json
{
  "dryRun": true,
  "valid": true,
  "sheets": [
    { "sheet": "技術者", "newCount": 12, "updateCount": 3, "errorCount": 0 },
    { "sheet": "案件", "newCount": 8, "updateCount": 0, "errorCount": 0 },
    { "sheet": "契約", "newCount": 15, "updateCount": 0, "errorCount": 0 }
  ],
  "errors": [
    { "sheet": "技術者", "row": 5, "message": "スキル『React.js』はスキルマスタに存在しません" }
  ],
  "createdAccounts": [
    { "email": "tanaka@example.com", "name": "田中太郎", "initialPassword": "..." }
  ]
}
```

- `errors` が1件以上ある場合、`valid: false` となり何も取り込まれない(dryRun=false でも同様)
- `createdAccounts` は dryRun=false で取り込みが成功した場合のみ返る

エラーレスポンスは共通仕様(`Docs/api-design.md` §3.1)に従う。ファイル形式不正・サイズ超過は 400。

## 7. 画面

`/import`(Sales のみ):

1. テンプレートダウンロードボタン
2. ファイル選択 → 自動でプレビュー実行
3. プレビュー結果: シートごとの新規/更新件数 + エラー一覧テーブル(シート/行/メッセージ)
4. エラーゼロのとき「取り込みを確定」ボタン有効化
5. 確定後: 作成されたアカウントと初期パスワードの一覧を表示(**この画面でしか見られない**旨を明記、CSVコピー可)
